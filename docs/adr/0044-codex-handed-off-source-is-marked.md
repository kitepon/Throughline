# ADR 0044: 引き継ぎが済んだ Codex の旧タスクの名前へ、引き継ぎ済みの印を付ける

日付: 2026-10-09

## Context

Codex Desktop の自動継続は、後継のタスクに `<project 名>｜<作業の概要>（自動引き継ぎ）` の名前を付ける（ADR 0037）。
概要は前任の題から取り、前任がこの形の名前を持つ後継なら中の概要だけを取り出す。project 名と印が積み重ならない
代わりに、2回目からの後継も1回目と同じ名前になる。

2026-10-09、オーナーから「スルーライン後に引き継ぎ先のcodexタスクが見つからない」と指摘があった。macOS の実機の
`session_index.jsonl` には、同じ名前の後継が4本（`BellTeam｜ベルチーム（自動引き継ぎ）`）と3本
（`approval-box｜ナユタとASCの状況を確認（自動引き継ぎ）`）あった。元のタスクも、引き継いだ後に名前が変わらない。
一覧を見ても、どれが今の続きかを名前で決められない。

確かめた事（Codex Desktop 同梱の Codex 0.162.0-alpha.2）:

- 後継は一覧から消えていない。Desktop と同じ条件（`thread/list`、`archived: false`、`useStateDbOnly: true`）で
  問い合わせると、その日の後継は2番目に入っていた（1番目は旧タスク）。
- Desktop が開いたままのタスクは、別の process から `thread/archive` できない（`already has an active writer`）。
  `thread/name/set` は通る。
- `thread/name/set` は、`thread/list` の `updatedAt` と `recencyAt` を変えない。一覧の並びは動かない。
- 引き継ぎ済みの旧タスクへ入力すると、止めた理由の文に後継の名前と link が出る（ADR 0039）。ここは足りている。

直し方は2つ考えた。旧タスクへ印を付ける形と、後継の名前へ何回目かの番号を付ける形。番号の形は、元のタスクに印が
付かず、番号を見比べる必要がある。オーナーは印の形を選んだ（Approval Box K-TFYVTM）。

## Decision

1. 後継が作業を続けたのを確かめた後（引き継ぎの `state` が `continued` になった直後）に、旧タスクの名前の頭へ
   `【引き継ぎ済み】` を付ける。一覧は名前の後ろを切るので、印は頭に置く。
2. 名前は、その時の旧タスクの名前を `thread/read` で読んでから作る。利用者が付け直した名前も残る。名前の無いタスクは、
   最初の依頼の1行目を使う（60 字で切る）。もう印がある名前、空の値、継続の指示が題として見えている後継には付けない。
3. 付けられなくても、引き継ぎは止めない。名前は表示だけに使う。理由は worker のログに残す。
4. 途中で止まった引き継ぎ（`failed`・`unknown`）の旧タスクには付けない。作業はまだ旧タスクにある。
5. 印の付いた名前から後継の名前を作る時は、印を外す（やり直しで、印の付いた旧タスクの題を読む事がある）。
6. 印を付けない版（0.16.9 まで）が引き継いだ分は、`throughline auto-handoff mark-sources` で付け直す。
   `continued` の引き継ぎの旧タスクを古い順に見て、生きている後継がある物だけに付ける。後継が消されている旧タスクは、
   今の続きなので付けない。何度流しても同じ結果になる。
7. 引き継ぎ済みの旧タスクへ入力した時の扱い（止めて後継を開く。ADR 0039）は変えない。

## Consequences

- 同じ作業の系列で、印の無いタスクは1本になる。それが今の続き。
- 利用者が付けた題を含めて、旧タスクの名前が変わる。元の名前は印の後ろに残る。
- 後継を消して旧タスクで作業を続ける時は、旧タスクに印が残る。名前は手で直せる。
- 引き継ぎ1回につき、app-server への接続が1回増える（`thread/read` と `thread/name/set`）。後継が作業を始めた後なので、
  引き継ぎの時間は変わらない。
- Claude Code の後継も同じ名前の付け方（ADR 0037）だが、旧い会話の名前を外から変える公式の入口を確かめていない。
  この ADR は Codex だけを扱う。
