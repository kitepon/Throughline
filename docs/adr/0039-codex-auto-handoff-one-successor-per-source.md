# ADR 0039: 引き継ぎ済みの Codex タスクへ新しい入力が来ても、後継を増やさない

日付: 2026-10-07

## Context

2026-10-07、macOS の Codex Desktop（Throughline 0.16.1、自動継続は全 project で有効）で、同じ作業を引き継いだ
後継タスクが3つ出来た。時刻は JST。

- 09:49:01 旧タスク `01a1136a` の自動圧縮を止め、後継 `01a113d5` を立てた（`continued`）。後継は 09:54:40 に
  ターンを終え、利用者の操作を待っていた。
- 09:56:48 旧タスク `01a1136a` へ、利用者の新しい入力（1行）が届いた。旧タスクは閾値を超えたままなので、
  `PreCompact(auto)` がもう一度発火した。Throughline はそのターンを止め、2つ目の後継 `01a113dc` を立てた。
- 09:56:58 同じ旧タスクへもう1行届き、3つ目の後継 `01a113dd` を立てた。

3つの引き継ぎは、どれも元が同じ旧タスクで、前任の引き継ぎも同じだった。2つ目と3つ目の後継は、1つ目の
後継が 09:49〜09:54 に進めた作業を知らないまま、同じ作業（本番の認証の確認）を始めた。3つ目が自分で
降りたので、操作は重複しなかった。

設計の受入条件は「同じ旧タスクから後継を重複作成せず、旧・新タスクが同じ操作を重複実行しない」
（[05_codex_first_roadmap.md](../05_codex_first_roadmap.md)）。実装が一意にしていたのは元 thread と元 turn の
組で、同じ旧タスクの別の turn は別の要求として受けていた。hook が同じ turn で2回走った時は増えないが、
旧タスクに新しい turn が出来るたびに後継が増える。

Claude Code の自動継続（ADR 0033）は、記録を旧い会話ごとに1つ持つ。引き継ぎ済みの会話で道具が呼ばれた時は、
後継を増やさずに止め、止めた理由に後継を書く。Codex の側をこの形にそろえる。

## Decision

1. Codex の `PreCompact(auto)` は、その旧タスクから継続の指示が届いた（届いたかもしれない）引き継ぎがあり、
   その後継のタスクが残っている時、新しい引き継ぎを作らない。`continue: false` でターンを止め、止めた理由に
   引き継ぎ ID、後継の名前、`codex://threads/<後継>` を書く。Desktop で後継を開く。
2. 「指示が届いた（かもしれない）」は、受付 ID が保存されている、状態が `submitted`・`continued`、
   または配送の途中（`mutation_stage` が `submit`。結果不明で止まった物を含む）のどれか。
   配送の前に失敗した引き継ぎは数えない。その旧タスクからは、今までどおり新しい引き継ぎを作る。
3. 示す後継は、今その作業を持っているタスクにする。後継がさらに引き継いでいれば、その先をたどる。
   後継の rollout が `sessions` に無い時（消した、アーカイブした）は、その後継は無い物として扱う。
   残っている後継が1つも無ければ、今までどおり旧タスクから新しい引き継ぎを作る。
4. 0.16.1 までに同じ旧タスクから複数の後継が立っている記録では、rollout が最後に書かれた後継を示す。
5. worker は、継続の指示を送る直前に、同じ旧タスクの別の引き継ぎが先に指示を送っていないかを確かめる。
   確認と「配送の途中」の記録は1つの transaction で行う。先に送られていれば、送らずに
   `handoff_source_already_continued` で失敗にする。2つの入力がほぼ同時に来て、hook の判定をどちらも
   通った時のための確認。
6. 止めた事は `~/.throughline/codex-auto-handoff/redirects.jsonl` に1行残す（時刻、旧タスクと turn、
   引き継ぎ ID、後継、開けたか）。会話の本文は書かない。引き継ぎの行は増えないので、起きた事はここで数える。
7. 同じ turn の hook がもう一度来た時は、今までどおり同じ引き継ぎを返す。手動の `/compact` は、
   今までどおり止めない。

## Consequences

- 旧タスクへ打った入力は、後継へは渡らない。旧タスクでターンが止まり、後継が開く。利用者は後継で
  打ち直す。入力を後継へ自動で送る事はしない（継続の指示は1回だけ送る、という配送の契約を変えないため）。
- 引き継ぎ済みの旧タスクは、後継が残っている間、そのタスクで作業を続けられない。旧タスクで続けたい時は、
  旧タスクで手動の `/compact` を使う。
- 2つの入力がほぼ同時に来て5に当たった時は、後に来た方の後継（記憶だけが入った、指示の無いタスク）が
  残り、失敗の表示が出る。
- 外から旧タスクへ届く文（旧タスクが開いた通話への返信など）も、同じように止まる。0.16.1 までは、
  1通ごとに後継が1つ増えていた。
