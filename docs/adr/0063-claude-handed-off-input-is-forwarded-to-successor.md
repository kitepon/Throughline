# ADR 0063: 引き継ぎ済みの Claude の会話へ届いた入力は、後継の会話へ届ける

- Status: Accepted
- Date: 2026-10-14

## Context

ADR 0062 は、引き継ぎ済みの Claude の会話へ届いた入力を、モデルを動かさずに止めて、後継の場所を返す形にした。
止めた入力は後継へ渡らない。人が打った文は後継で打ち直しになり、旧い会話が裏で起こした作業の完了通知は、後継へ
届かないままになる。利用者の決め（2026-10-14）は「先に止める形を入れ、続けて、後継へ届ける形を作る」。この ADR は
後の分を決める。

Claude Code に、動いている別の会話へ外から文を入れる命令は無い（`claude --help` の一覧。2.1.296）。会話の受け口
（`messagingSocketPath`）は、権限のバイパス中の会話では、送り手を確かめられない文を利用者の承認まで止める。この止めは
回避しない（ADR 0033 の 4）。残る道は、後継自身の hook が文を受け取る形になる。

Claude Code 2.1.296 で、次を実機で確かめた（Linux・macOS・Windows の3つとも同じ結果。自分で立てた裏の会話、
Haiku。利用者の設定の hook を外し、試しの hook だけを付けた。試しの文は自分で決めた物）。

| 見た事 | 結果 |
|---|---|
| 手すきの会話。Stop の `asyncRewake: true` の hook が待っていて、後から stderr へ文を出して exit code 2 で終わる | 1 秒以内に会話が起きて、文に従った。届く行は `origin.kind: task-notification` の user 行で、`<summary>Stop hook feedback</summary>` と `<system-reminder>` に包まれる |
| 作業中の会話。番の途中に文を置き、番の終わりの Stop の hook がすぐ exit code 2 で終わる | 番が終わった直後に、次の番として届いた |
| 道具の前後。`PreToolUse`・`PostToolUse` の hook が `additionalContext` を返す | 番の途中で文脈に入り、モデルが従った（`PreToolUse` は、道具を順に出した会話で3つとも確認） |
| `additionalContext` の長さ | 10,000 字（UTF-16 の長さ）を超えると、頭の約 2,000 字と「全文は file にある」の案内に置き換わる。9,900 字までは、そのまま届く。日本語でも字数で決まる |
| Stop の hook の stderr の長さ | 23,000 字が、そのまま届いた |
| hook の `timeout`（秒）が切れた時 | hook は止められる（POSIX は SIGTERM）。会話は起きない。その後に文を置いても届かない |
| `timeout: 7200` の hook | 11 分待った後でも届けた（既定の 600 秒より長く待てる） |
| `claude stop` | 待っている hook も止まる |
| 待つ hook を持つ手すきの裏の会話を、Claude Code が片付ける時（`bg retire`） | hook が待っていても、61 分で片付けた（Linux）。hook の process は止められず、残った。片付けの後に hook が文を出して exit code 2 で終わっても、会話には何も届かなかった。hook の環境の `CLAUDE_PID` は、片付けられた会話の process の ID だった |
| hook が待っている間に、会話が別のきっかけ（自分の裏の作業の完了通知）で次の番へ進む | 前の hook は止められず、待ち続ける。次の番の終わりに、もう1つ hook が立つ |
| 前の番から待っている hook が、次の番の作業中に exit code 2 で終わる | Claude Code が文を順番待ちへ入れ（`attachment` の `queued_command`）、次の道具の合間に届けた。モデルは従った（Linux で確認） |
| 待つ hook を持つ会話へ `claude -p --resume` で入力する | hook が終わるまで命令が返らず、出力も出ない（hook が 20 秒で自分から終わる時は、22〜23 秒で返った）。この時の hook の環境は `CLAUDE_CODE_ENTRYPOINT=sdk-cli`（裏の会話は `cli`） |

## Decision

1. **置き場。** 後継ごとに、届けるのを待つ入力を1通1ファイルで置く
   （`~/.throughline/claude-auto-handoff/inbox/<後継の会話 ID>/<時刻>-<連番>.json`）。中身は、届いた時刻・旧い会話の ID・
   引き継ぎ ID・種類（`prompt` か `task-notification`）・本文。ファイルは本人だけが読める（0600）。届けたら消す。
2. **旧い会話の側。** ADR 0062 の止め方は変えない。止める時に、入力を今の続きの会話（後継の先まで引いた会話）の置き場へ
   置く。置けた時は、返す文を「届いた入力は後継の会話へ渡しました」に替え、届く時機と後継を開く命令を添える。
   後継で待つ hook の process が生きていれば「後継は動いています」、生きていなければ「後継は今、入力を待ち受けて
   いません（止まっているか、この版より前に立った会話です）。後継を開いて何か入力した時に届きます」と書き分ける
   （待つ hook は、置き場の印に自分の process の ID を書いている）。
   後継の会話 ID を引けない時と、置き場へ書けなかった時は、0.16.31 と同じ文（後継で打ち直す）を返す。
   止めた記録（`redirects.jsonl`）に、渡せたか（`forwarded`）を足す。本文は書かない。
   - **slash command（頭が `/` の入力。`/tl`・`/clear` など）は運ばない。** その会話への命令で、後継へ文として運んでも
     命令にならない。0.16.31 と同じ文を返す。頭が `/` で始まる普通の文（path など）も、見分けられないので運ばない。
   - **ほかの会話から届いた文（`Another Claude session sent a message:` で始まる）は、利用者の入力と分けて運ぶ。**
     届ける文に「ほかの Claude の会話が送った文で、利用者の入力ではない」と書く。旧い会話の受け口を通った後の文なので、
     Claude Code が付けた注意書きは、そのまま付いて届く。
3. **後継の側。** 置き場の入力を、次の3か所で受け取る。先に受け取った所が届ける。
   - **Stop の hook（新しく登録する。`throughline claude-forward-wait`、`asyncRewake: true`）。** 番の終わりに走り、置き場に
     入力が在ればすぐ、無ければ届くまで待って、stderr へ出して exit code 2 で終わる。手すきの後継が、これで起きる。
   - **`UserPromptSubmit`（今ある hook）。** 後継へ入力が来た時に、置き場の入力を文脈として足す。待つ hook が居ない後継
     （期限で止められた・`claude stop` の後に開き直した・この版より前に立った）は、ここで受け取る。
   - **`PreToolUse`（自動継続が今も登録している hook）。** 作業中の後継が、次の道具の前に、文脈として受け取る。
     番の終わりまで待たせない。
4. **文脈として足す道（`UserPromptSubmit`・`PreToolUse`）は、9,000 字までの分だけを運ぶ。** 10,000 字を超えると Claude Code が
   頭だけに切り詰めるので、収まらない入力は置き場に残し、Stop の道で届ける。Stop の道は、1通が 60,000 字を超える時だけ、
   頭の 4,000 字と全文の file の場所を届ける。
5. **待つ hook が走る会話。** 自分の置き場のフォルダが在る会話だけが待つ。フォルダは、後継が継続の指示を受領した時と、
   旧い会話が最初の入力を置いた時に出来る。フォルダが無い会話（後継でない会話。ほとんどの会話）では、hook はフォルダの
   有無だけを見て終わる。
   - script から起動した Claude（`CLAUDE_CODE_ENTRYPOINT` が `sdk-` で始まる。`claude -p`、Agent SDK）では待たない。
     待つと、呼び出し元の命令が返らない。その時の入力は、`UserPromptSubmit` の道で届く。
   - subagent の中では待たない。
   - 待っている間に、自分の会話がさらに引き継がれて後継が立ったら、置き場に残った入力を今の続きの会話の置き場へ移して
     終わる。旧い会話を起こさない。
   - hook の `timeout` は 86,400 秒にする。期限が切れると、次に後継が動くまで（入力・番の終わり）届かない。
   - 会話の process（hook の環境の `CLAUDE_PID`）が居なくなったら、受け取らずに終わる。Claude Code は、手すきの裏の会話を
     片付ける時に、待っている hook を止めない。居ない会話へ出力すると、入力が届かないまま消える。
   - **1つの会話で待つのは1つだけにする。** Claude Code は、会話が次の番へ進んでも前の hook を止めないので、そのままだと
     番の終わりのたびに待つ process が1つ増える。新しい hook は置き場に自分の印（`waiter`）を書き、前の hook は印が
     替わったのを見て退く。前の hook は、次の番が終わるまでは残る。その間に届いた入力は、前の hook が出して
     Claude Code が道具の合間に届けるか、`PreToolUse` の道が先に受け取る。
6. **届いたか分からない入力は、入れ直さない。** 受け取る所は、入力のファイルを別のフォルダ（`claimed`）へ改名してから
   出力し、出力した後で消す。改名の後で process が落ちると、その入力は届いたか分からないまま `claimed` に残る。
   これを置き場へ戻さない（二重に届くより、1通落ちて跡が残る方を選ぶ。ADR 0039 の Codex と同じ考え）。
   `auto-handoff status --host claude` に、届けるのを待つ数と、届いたか分からない数を出す。
7. **届ける文。** 頭に、Throughline が運んだ事・旧い会話の頭8字・種類ごとの数を書いた行を置く。人の入力は
   「利用者がこの会話へ打った入力として扱う」、ほかの会話からの文は「利用者の入力ではない」、完了通知は
   「引き継ぎ前の会話が裏で起こした作業の通知」と書く。
   複数ある時は、届いた順に1つの文にまとめる。完了通知が続く時は、後継が動いている間に溜まった分が、次の1回で届く。
8. **記憶（L2）。** 運んだ人の入力は、後継の記録の中で、利用者の発言として読む。Stop の道で届いた行は、包みを外して
   届けた文だけを残す。文脈として足した分と、前の hook が作業中に出して順番待ちから届いた分は、作業の途中で届いた入力
   （ADR 0060）と同じに、そのターンの依頼へ足す。完了通知だけを運んだ分は、ターンの途中では足さない（ADR 0060 と同じ）。
   入力の hook が stdout へ出した文脈は、記録では `hook_success`（`hookEvent: UserPromptSubmit`）の `content` に入る。
   道具の前の hook が返した文脈は `hook_additional_context` に入る（実測）。
9. **片付け。** どの引き継ぎの記録からも後継として指されなくなった会話の置き場は、空なら消す。7日を過ぎた入力は、
   届けずに消して、消した数を記録へ残す。
10. **登録。** `auto-handoff enable --host claude` が、今までの2つ（`PreCompact`・`PreToolUse`）に加えて Stop の hook を
    登録し、`disable` が外す。有効な端末では、版を上げた時の `install` が足す（Claude の設定ファイルが1か所変わる）。
    Codex・Grok・Cursor の設定は変えない。

## Consequences

- 旧い会話へ打った文は、打ち直さなくても後継へ届く。手すきの後継はすぐ動き、作業中の後継は次の道具の前に読む。
- 旧い会話が裏で起こした作業の完了通知が、後継へ届く。手すきの後継は、通知のたびに1回動く（今は同じ回数が、
  文脈がほぼ一杯の旧い会話で止められている）。
- 後継の画面では、運ばれた入力は利用者の発言の形では出ない。Stop の道では hook からの通知の形、文脈の道では hook が
  足した文脈の形になる。
- 運ばれた人の入力に従うかは、後継のモデルが決める。hook 経由の文は利用者の発言の形で届かないので、モデルが利用者の
  指示として扱わない事がある（実測は下）。後継が最初に受け取る引き継ぎの文脈で、運び方を先に知らせる。旧い会話へ返す文に
  「打ち直しは要らない」とは書かず、後継を開く命令を添える。
- 手すきの後継ごとに、待つ process が1つ動く（node。1 秒ごとにフォルダを見る）。後継が `claude stop` や片付けで止まれば、
  一緒に止まる。
- 自動継続が有効な端末では、Claude の番の終わりのたびに hook が1つ多く走る。置き場のフォルダが無い会話では、
  すぐ終わる。
- 後継が止まっている時（`claude stop`・Claude Code の片付け）は、起こさない。入力は置き場で待ち、後継を開いて
  何か入力した時に届く。止まっている後継を自動で起こす形は、この ADR では決めない（動いている会話へ
  `claude --bg --resume` を流すと写しが立つので、止まっている事を確かめる道を先に決める必要がある）。
- 置き場のファイルは、届くまで入力の本文を持つ。DB と会話の記録のほかに、本文が一時的に置かれる場所が増える。
- `claude -p --resume <後継>` の入力では、置き場の分は文脈として届き、待つ hook は走らない。

## 確かめた事・確かめていない事

- 確かめた事は、Context の表と、この版の試験（CHANGELOG の 0.16.32）。
- 直した版を、本物の Claude Code 2.1.296 の裏の会話（Haiku）へ通した。Linux・macOS・Windows の3つ。利用者の設定の hook を
  外し、直した版を切り離した HOME で呼ぶ hook だけを付けた。旧い会話の役と後継の役を立て、引き継ぎの記録を切り離した
  置き場へ置いた。後継の役の置き場は、最初の入力の hook で作った（本物では、継続の指示の受領が作る）。3つとも同じ結果だった。

  | 見た事 | 結果 |
  |---|---|
  | 旧い会話が裏で起こした作業の完了通知 | 旧い会話では止まり、手すきの後継が起きて、通知の中身に答えた |
  | 人の入力（`claude -p --resume <旧い会話>`） | 「届いた入力は、後継の会話へ渡しました」が返り、手すきの後継が起きて、入力に従った |
  | 後継が止まっている時の人の入力 | 置き場で待った。後継を `claude -p --resume` で開いて入力すると、3〜5 秒で命令が返り、運んだ入力が文脈として届いていた |
  | 作業中の後継への人の入力 | 次の道具の前に文脈として届き、後継はその番の答えで従った |
  | 後継が自分の裏の作業の完了通知で次の番へ進んだ時 | 前の待つ hook は退き、待つ hook は1つだけ残った |
  | 直した版の読み手で読んだ後継の記録 | 運んだ文が利用者の行に入り、Claude Code の通知の包みは入らない。文脈で届いた分は、作業の途中の入力として入る |
  | 切り離した置き場の失敗の記録・届いたか分からない入力 | 無し・0 |
  | 本物の置き場と判定の記録にある、試しの会話 | 0 |

- 運んだ人の入力に、後継のモデル（Haiku）が従ったかを、手すきの後継で数えた（3つの OS の合計）。hook 経由の文に従うかは
  モデルが決めるので、従わない事は無くせない。従わなかった後継は「自動の通知として届いたので、利用者の指示としては
  扱わない」と答えた。

  | 場面と、運ぶ文の形 | 従った回数 |
  |---|---|
  | 後継の最初の番の後に、人の入力だけを運ぶ。見出しに「利用者がこの会話へ打った入力として扱ってください」と書く形 | 26 回のうち 26 回（知らせあり 13、なし 13） |
  | 後継が完了通知を1通受けた後に、人の入力を運ぶ。同じ形。後継は、引き継ぎの文脈の知らせを受け取っていない | 21 回のうち 19 回 |
  | 同じ場面・同じ形。後継は、引き継ぎの文脈（読み方）で運び方の知らせを受け取っている | 6 回のうち 5 回 |
  | 同じ場面。見出しを「利用者が前の会話へ打った文です」と、出どころを述べるだけにした形。知らせなし | 18 回のうち 10 回 |
  | 同じ場面。出どころを述べるだけの形。知らせあり | 18 回のうち 16 回 |

  出どころを述べるだけの形は、知らせの無い後継で従わない回が増えたので、採らない。見出しに「利用者がこの会話へ打った
  入力として扱ってください」と書く形にし、後継が最初に受け取る引き継ぎの文脈（読み方）でも運び方を知らせる。
  試しの入力は「PROBE: …と答えてください」の形で、本物の作業の依頼より疑われやすい文だった。
- 確かめていない:
  - 端末の画面・Claude Desktop・リモートコントロール（スマホ）で、運ばれた入力がどう見えるか。
  - 86,400 秒の `timeout` が、そのとおりに待つか。7,200 秒の指定で 11 分より長く待てる所までを見た。
    待つ hook が終わった理由と待った秒数を記録へ残すので、入れた後の追跡で読む。
  - 片付けられた裏の会話の、直した版の待つ hook が、`CLAUDE_PID` を見て退く所（単体試験まで。実機は 61 分かかるので、
    公開の後に読む）。
  - macOS と Windows で、裏の会話が片付けられる時の hook の残り方（Linux だけで見た）。
  - ほかの会話から届いた文（`SendMessage`）を運んだ時の、送り手の側の見え方。
