# ADR 0061: Codex が自分で起こしたターンの入力は、印とゴールの文だけを記憶に残す

- Status: Accepted
- Date: 2026-10-14

## Context

Codex は、ゴール（`/goal`）が実行中のタスクで、手すきになるたびに自分で次のターンを起こす（ADR 0059）。そのターンの入力は、
rollout に user の発言（`response_item` の `message`、`role: "user"`）として入る。本文は `<codex_internal_context source="goal">` で
始まり `</codex_internal_context>` で終わる。中身は、続け方の決まりを書いた定型文で、利用者が決めたゴールの文を
`<objective>` … `</objective>` に持つ。Linux の実機の試験タスクで読んだ1通は 6,343 字で、ゴールの文はそのうち約 200 字だった。

この製品は、user の発言から `# AGENTS.md instructions` と `<hook_prompt` で始まる物だけを外していた。ゴールの続行の入力は、
利用者の発言としてそのまま L2 に入っていた。

2026-10-13 の Windows の実機のタスクでは、L2 の user 15 行のうち 7 行がこの入力で（各 6,293 字）、user の字数の 87% を占めていた
（行の数と長さだけを読んだ。本文は読んでいない）。ゴールで動かすタスクでは、引き継ぎの記憶に入る直近のターンの user の本文が、
同じ定型文の繰り返しになる。記憶の字数の枠を定型文が使い、利用者が実際に打った依頼が押し出される。

ゴールそのものは、ADR 0059 で、引き継ぎの時に後継へ運んでいる。記憶に定型文を残す理由は無い。

## Decision

1. user の発言が `<codex_internal_context` の開く印で始まり、閉じる印 `</codex_internal_context>` を持つ時、開く印（属性ごと）・
   `<objective>` … `</objective>`（あれば）・閉じる印だけを残す（`compactCodexInternalContext`）。ほかの中身は落とす。
   - 開く印の `source` は、何のターンかを表すので残す。
   - ゴールの文は、利用者が決めた文なので残す。そのターンが何を目指して動いたかが、記憶から読める。
   - 閉じる印の後ろに文があれば、残す。
   - 閉じる印が無い時は、何も落とさない。形が分からない物を推測で切らない。
   - 発言の途中に印がある物（頭に別の文がある物）は、触らない。
2. ターンは落とさない。user の行は短い行として残る。ターンの番号の数え方は変えない。
3. 同じ正規化を、user の発言を読む3か所（`event_msg` の `user_message`、`response_item` の `message`、圧縮で置き換わった履歴）に
   通す。巻き戻しの照合は、3か所の本文を比べるので、揃えておく。
4. 判定は印だけで行う。定型文の言い回しは読まない。Codex が定型文を変えても、印と `<objective>` が同じなら動く。

## Consequences

- ゴールで動くタスクの L2 で、続行のターンの user の行が、約 6,300 字から「印 + ゴールの文」になる。
- Codex の取り込みは、タスクの bodies を毎回全部入れ直す。前の版が保存した長い行は、次の取り込みで短い行に置き換わる。
  本文が変わったターンの L1 の要約は消えて、作り直される（今までの決まりのまま）。
- 引き継ぎ済みの旧タスクは、取り込みが走らないので、前の版が保存した行のまま残る。
- `<objective>` の中身は、Codex が書いた形のまま残る（`&lt;` などの置き換えを戻さない）。
- Claude Code・Grok・Cursor には、この形の入力が無い。変えない。

## 確かめた事・確かめていない事

- 確かめた:
  - 単体試験（定型文を落とす、後ろの文を残す、ゴールの文が無い形、閉じる印が無い・頭に無い・似た名前の印を触らない、
    rollout を通した時の3つのターン）。
  - 本物の rollout へ、前の版と直した版の読み手を当てて比べた（DB は開かない。数だけ）。3つの OS とも、ターンの数と行の数は同じで、
    続行の入力でない user の行と assistant の行は1つも変わらない。

    | | 続行の入力のある rollout | 続行の入力の行 | その字数 | 直した後の一番長い行 |
    |---|---|---|---|---|
    | Linux | 9 本（試験のタスク） | 17 → 17 | 107,635 → 5,491 | 323 字 |
    | macOS | 9 本（本物 1 本と試験のタスク） | 21 → 21 | 132,486 → 6,248 | 536 字 |
    | Windows | 7 本（本物 3 本と試験のタスク） | 2,069 → 2,069 | 13,020,355 → 579,482 | 691 字 |

  - 取り込みの入口（`codex-capture`）へ、試験のタスクの rollout の写しを、使い捨ての HOME で、前の版 → 直した版 → 直した版の順に
    通した（3つの OS）。前の版が入れた長い行（6,335〜6,567 字）が、直した版の取り込みで短い行（323〜557 字）に置き換わり、行の数と
    details は変わらない。もう1回通しても同じ。
- 確かめていない: `source` が `goal` 以外の `<codex_internal_context>`。実物を見ていない。同じ形（開く印と閉じる印）なら、
  印だけが残る。直した版を入れた端末で、本物の Codex がゴールの続行のターンを終えた時の L2 は、入れた後の追跡で読む。
