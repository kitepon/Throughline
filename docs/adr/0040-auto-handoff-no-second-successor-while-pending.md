# ADR 0040: 引き継ぎの最中と、止まった引き継ぎから、2つ目の後継を立てない

日付: 2026-10-07

## Context

ADR 0039（0.16.2）は、継続の指示が届いた後継が残っている旧タスクから、2つ目の後継を立てない様にした。
オーナーは、1つのタスクや会話で自動継続が2回以上発動しない事を求めた（2026-10-07）。0.16.2 のコードを動かして、
同じ旧タスクから2つ目の後継が立つ道が残っている事を確かめた。

Codex:

1. **引き継ぎの最中の入力。** worker が継続の指示を送る前（macOS の実績で、要求から継続の確認まで 9〜74 秒）に
   旧タスクへ入力が来ると、`PreCompact(auto)` がもう一度発火する。ADR 0039 の判定は「指示が届いた引き継ぎ」だけを
   見るので、別の引き継ぎを作った。1つ目の worker は、元の turn が最新でなくなった事を `handoff_source_advanced` と
   判定して失敗し、失敗の画面を出す。1つ目が作った後継（記憶だけが入り、指示は無い）が残り、2つ目の引き継ぎが
   別の後継を立てる。
2. **後継を作った後、配送の前に止まった引き継ぎ。** 次の入力で、やり直しではなく別の引き継ぎを作った。
   前の後継が残り、後継が2つになる。

Claude Code:

3. **記録の期限。** 記録は24時間で掃除していた（ADR 0033 の10）。掃除の後、引き継ぎ済みの会話で自動圧縮が起きると、
   同じ会話からもう1つ後継が立つ。

hook が止めた入力の turn は、Codex Desktop 0.160.1 の rollout に次の並びで残る（2026-10-07 の実物）。
`thread_settings_applied`、`task_started`、user の `message`、`item_completed`、約1秒後の `turn_aborted`。
モデルの発言も道具の呼び出しも無い。

オーナーは3つの案から「止める場所は今のまま、穴だけ塞ぐ」を選んだ（2026-10-07）。入力を受けた時点で断る案
（`UserPromptSubmit` の `decision: "block"`。Codex 0.160.1 と Claude Code 2.1.292 の実物で、モデルが呼ばれない事を
確かめた）と、DB の一意を元タスクだけにする案は採らない。

## Decision

1. Codex の `PreCompact(auto)` は、その旧タスクに、継続の指示をまだ送っていない引き継ぎがあり、その worker が
   動いている時、新しい引き継ぎを作らない。`continue: false` でターンを止め、止めた理由に進んでいる引き継ぎの ID を書く。
   worker が動いているかは、記録の worker の process（pid と誕生時刻）が process 一覧にあるかで見る。
   worker を起動してから worker が名乗るまでの間（15 秒）は、記録の更新時刻で見る。
   process 一覧を読めない時は、記録の更新から 10 分の間だけ、動いている物として扱う（後継を2つにしない側へ倒す）。
2. 入力を受けただけで止まった turn は、元 turn の境界を進めない。worker は、元 turn より後の turn がどれも
   「止まっていて、モデルの発言・道具の呼び出し・完了・圧縮が無い」時、今までどおり引き継ぎを続ける。
   後の turn に動きがあれば、今までどおり `handoff_source_advanced` で止まる。まだ止まり切っていない turn は、
   止まるまで待つ（30 秒。過ぎれば `handoff_source_stop_unconfirmed`）。
3. 止めた後で旧タスクへ来た入力は、凍結する記憶へ入れない。後継へは渡さない入力（ADR 0039 の Consequences）。
4. 後継を作った後、配送の前に止まった引き継ぎは、次の入力で同じ引き継ぎをやり直す。条件は、後継のタスクが
   残っていて、後継にまだ turn が無く、止まった後の旧タスクに動きが無い事。`failed` は止まった工程から再開し、
   worker が居なくなった途中の記録はその状態から続ける。
   条件に合わない時（後継を利用者がもう使っている、後継が消えている、結果不明、旧タスクが進んでいる）と、
   後継を作る前に止まった引き継ぎからは、今までどおり新しい引き継ぎを作る。後継を作る前の失敗は、残る物が無い。
5. 2つの入力がほぼ同時に来た時は、先に記録した方だけが引き継ぎを作る。「継続の指示をまだ送っていない引き継ぎが
   増えていないか」の確認と記録を、1つの transaction で行う。後から来た方は、1の扱いになる。
   ADR 0039 の5（worker が指示を送る直前の確認）は残す。
6. 1と4で止めた事は、`~/.throughline/codex-auto-handoff/redirects.jsonl` に `kind`（`in_flight`・`retry`）を付けて残す。
   ADR 0039 の行（後継を示した回）には `kind` を付けない。
7. Claude Code の記録は、後継の会話が残っている間は、24時間を過ぎても掃除しない。後継が残っているかは、
   受領が残った引き継ぎ（`sent`）について、後継の transcript があるかで見る。transcript は、旧い会話の transcript の
   場所から Claude の projects をたどり、その下のフォルダを順に見る（フォルダ名の付け方は OS で違う）。
   後継が消えた記録、受領を確かめられなかった記録、失敗した記録は、今までどおり期限で掃除する。
8. DB の形は変えない（v12）。ADR 0039 の3（後継が残っていない旧タスクからは、新しい引き継ぎを作る）は変えない。

ADR 0039 の2のうち「配送の前に失敗した引き継ぎからは、今までどおり新しい引き継ぎを作る」は、4で置き換える。
ADR 0033 の10のうち「24時間を過ぎたものは次の引き継ぎの時に掃除する」は、7で置き換える。

## Consequences

- 引き継ぎの最中に旧タスクへ打った入力は、止まる。後継へは渡らない。後継が開いてから、後継で打ち直す。
- 引き継ぎの最中に来た入力では、失敗の画面は出ない。記憶だけが入った後継も残らない。
- 後継を消した（アーカイブした）旧タスクからは、今までどおり新しい後継が立つ。1つの旧タスクから後継が2つ出来るのは、
  この時と、4の条件に合わなかった時だけになる。
- 旧タスクが圧縮に掛からない間（手動の `/compact` の後など）は、旧タスクはそのまま動く。止めるのは `PreCompact(auto)` の時だけ。
- Claude Code の引き継ぎ済みの会話は、後継が残っている間、道具と圧縮を止め続ける。道具を呼ばない会話は続けられるが、
  圧縮されないので、続けると文脈の上限に当たる（0.16.2 までも、記録が残っている間は同じ）。
- worker が動いているかを見るために、`PreCompact(auto)` の hook が process 一覧を読む事がある。読むのは、その旧タスクに
  途中の引き継ぎがあり、worker が名乗っている時だけ。

## 確認した範囲

- 0.16.2 のコードで、1・2・3の道を再現した（切り離した HOME と空の DB）。
- hook が止めた turn の並びは、macOS の Codex Desktop（同梱の Codex 0.160.1）で 2026-10-07 に起きた2回の記録を読んだ。
- macOS（公開する tarball、切り離した HOME、本物の `codex_handoffs` の写し）。
  - 2026-10-07 の実物の rollout（元 turn の後に、hook が止めた入力が2つ）で、境界の判定は「止まったまま」になった。
    0.16.2 は同じ rollout を `handoff_source_advanced` と判定する。
  - 1つ目の引き継ぎを指示を送る前の状態へ戻した写しへ、本物の入口（`codex-hook pre-compact`）で新しい turn を渡した。
    `continue: false`、新しい行 0、worker の起動 0、Desktop を開く呼び出し 0。worker が名乗る前（更新時刻）と、
    worker が動いている時（macOS の process 一覧）の両方で同じ。worker が居なくなり後継も残っていない時は、新しい引き継ぎを作った。
  - 引き継ぎ済みの旧タスクへの入力（ADR 0039）と、引き継いでいないタスクは、0.16.2 と同じ動き。
- 同じ旧タスクへ6つの入力を同じ時刻に入れた（本物の process、Linux は5回、macOS は3回）。どの回も、引き継ぎの行は1つ、
  worker の起動は1回。0.16.2 は6つずつ出来る。
- hook の本体と worker の本体を通した（Linux、Codex Desktop に触る所だけ差し替え）。最中に来て止まった入力では、
  1つ目の引き継ぎが `continued` まで進み、失敗の画面は出ず、凍結した記憶に後から来た入力は入らなかった。
  旧タスクでモデルが答えた時は、後継を作る前に `handoff_source_advanced` で止まった。

## 確認していない範囲

- 本物の Codex Desktop での通し（引き継ぎの最中に、画面から旧タスクへ打つ）。画面で、止めた理由がどう見えるか。
- 4（同じ引き継ぎのやり直し）を、本物の後継のタスクで。後継にまだ turn が無い状態は、試験の差し替えでだけ見た。
- Windows と Linux の Codex Desktop。Codex の自動継続は macOS でだけ使われている。
- 7（Claude Code の記録を残す事）を、本物の Claude Code の会話で。試験で、transcript のフォルダが同じ時と別の時を見た。
