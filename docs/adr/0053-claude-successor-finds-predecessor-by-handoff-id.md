# ADR 0053: Claude の自動継続の後継は、引き継ぎ ID で前任を決める

- Status: Accepted
- Date: 2026-10-11

## Context

Claude Code の自動継続（ADR 0033）は、`PreCompact(auto)` で圧縮を止めて引き継ぎを予約し、次の `PreToolUse` で旧い会話を止めて
後継を立てる。後継が前任の記憶を受け取る所は、`/tl` と同じ仕組みを使っていた。予約の時に `handoff_batons`（project ごとに1行）へ
「この project の次の新しい会話は、この会話の続き」という印を書き、後継の最初の `UserPromptSubmit` がその印を取って合流する。

印には、自動継続に合わない所が3つあった。

- 印を書くのは予約の時で、後継が立つ時ではない。待ちに入っている会話は、次に道具を使うまで止まらない。印の期限は1時間。
- 印は project に1つ。同じ project の別の会話が予約すると、上書きされる。
- 印は、その project で次に最初の指示を受けた新しい会話が取る。後継より先に別の会話が指示を受けると、その会話が前任の記憶を合流させる。

2026-10-11、Windows の実機（0.16.23）で起きた。同じフォルダに、役の違う Claude の会話が何本も動いていた。ある会話が 17:21:55 に
引き継ぎを予約し、道具を使って止まったのは 19:43:09 だった。その間の 18:43:06 に、同じフォルダの別の会話が最初の指示を受け、
印は期限切れ（81分）として消された。19:43:14 に後継が最初の指示を受けた時、印は無く、記憶は1文字も入らなかった。引き継ぎは
`unknown`（`handoff_delivery_unconfirmed`）で終わった。後継は記憶なしで自分で現在地を拾い、別の役の仕事を始めた。同じ役の会話が
2つ同時に動き、止めた会話が受けていた依頼は、だれも始めなかった。

後継の最初の指示は、文の頭に `Throughline自動継続 <引き継ぎID>` を持っている。引き継ぎの記録（旧い会話の session id で持つファイル）には
同じ引き継ぎ ID と、後継の ID の頭8字が入っている。前任を決めるのに要る物は、印が無くてもそろっていた。

## Decision

1. 後継の最初の `UserPromptSubmit` は、届いた指示の頭の引き継ぎ ID から記録を引き、その記録の旧い会話を前任として合流させる。
   project ごとの印は見ない。取りもしない。
2. 引き継ぎ ID で前任と認めるのは、記録が後継を立てている状態（`launching`・`launched`・`sent`・`unknown`）で、記録に後継の ID の頭が
   入っている時はそれと合う会話だけ。文の途中に引用された引き継ぎ ID は、配送として扱わない。
3. 自動継続は、予約の時に project ごとの印を書かない。`/tl` の印は今までどおり（利用者が、次の新しい会話を前任の続きにすると
   決めた時の物）。
4. 0.16.23 までの版が書いた印が残っている時は、後継が合流した時に、その前任を指す印を消す。
5. ある会話の今の続きを引く口を、Claude にも作る（`auto-handoff successor --host claude --thread <session id> --json`）。
   記録を先までたどり、後継の session id が記録に無い時（受領を確かめられなかった引き継ぎ）は、transcript の名前から引く。
6. 受領を確かめられなかった引き継ぎ（`unknown`）の記録も、後継の transcript が残っている間は、期限（24時間）で消さない。
   消すと、旧い会話がまた道具を使えるようになり、同じ会話から2つ目の後継が立つ。

## Consequences

- 同じ project に Claude の会話が何本あっても、後継は自分の前任の記憶だけを受け取る。予約から止まるまでが何時間あっても同じ。
- 同じ project で始まった別の新しい会話へ、引き継ぎ中の会話の記憶が入らない。
- 自動継続が、利用者の `/tl` の印を上書きしない。
- 引き継ぎの記録が消えた後（後継の transcript も無い時）に届いた継続の指示は、前任を引けず、記憶は入らない。
- 旧い会話は、記録がある間、文を受ければ文で答える。道具は断る（変えていない）。旧い会話あての連絡を今の続きへ渡すのは、
  連絡を運ぶ側の仕事で、5 の口で今の続きを引ける。
- 記憶が入らなかった後継へ、後から記憶を入れる処理は無い。`throughline recall --session <旧い会話の id>` で引ける。
- ほかの製品が、次の2つの形に頼っている（通話MCP `grokbot-bridge` 0.3.6 の `UserPromptSubmit` の hook。後継へ、前任が持っていた
  通話の引き取りを知らせる）。変える時は、先にその製品の担当へ知らせる。
  - 後継の最初の指示の頭: `Throughline自動継続 ` に続けて、36字の引き継ぎ ID。
  - `auto-handoff status --host claude --operation <引き継ぎID> --json` の `handoffs[0].source_session_id`。
