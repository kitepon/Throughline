# ADR 0064: 止まっている後継の会話は、人が旧い会話へ打った文で起こして届ける

- Status: Accepted
- Date: 2026-10-14

## Context

ADR 0063 は、引き継ぎ済みの Claude の会話へ届いた入力を、後継の会話へ届ける形にした。後継が止まっている時
（`claude stop`、Claude Code が手すきの裏の会話を 61 分で片付けた時）は起こさず、入力は置き場で待ち、後継を開いて何か
入力した時に届く。後継が片付けられた後で旧い会話へ打った文は、利用者が後継を開くまで届かない。

利用者の決め（2026-10-14、「止まっている後継の会話へ届いた入力を、どう扱うか」）は「人が打った文の時だけ、止まっている
後継を自動で起こして届ける。完了通知では起こさない」。その時に示した条件は「動いている会話へ起こす命令を流すと写しが
立つので、止まっている事を確かめる道を 3 つの OS で確かめてから出す」。

Claude Code 2.1.296 で、次を実機で確かめた（Linux・macOS・Windows の3つとも同じ結果。自分で立てた裏の会話、Haiku。
利用者の設定の hook を外し、試しの hook だけを付けた。試しの文は自分で決めた物）。

| 見た事 | 結果 |
|---|---|
| `claude agents --json --all` の項目（手すきで動いている裏の会話） | `state: done`・`status: idle`・`pid` がある |
| 同（作業中） | `state: working`・`status: busy`・`pid` がある |
| 同（手すきの時に `claude stop` で止めた） | `state: done`。`status` と `pid` の鍵が無い |
| 同（作業の途中で `claude stop` で止めた） | `state: stopped`。`status` と `pid` の鍵が無い |
| 同（Claude Code が 61 分で片付けた） | `state: done`。`status` と `pid` の鍵が無い（3つとも。macOS・Windows は公開の後に読んだ） |
| 同（コンテナごと止められた） | `state: done`。`status` と `pid` の鍵が無い（Linux） |
| 同（`claude rm` で消した） | 一覧に出ない。transcript は残る。立てた時の option の控え（`~/.claude/jobs/<頭8字>/state.json`）は消える |
| 同（止めた裏の会話を、端末の `claude --resume` で開いている・`claude -p --resume` が走っている） | 裏の項目（`pid` なし）とは別に、同じ会話 ID の `kind: interactive` の項目が `pid`・`status` 付きで出る |
| 同（無い会話 ID へ `--bg --resume` を流した直後） | その ID で新しい会話が立ち、8 秒後も `state: working` で `pid` がまだ無い |
| 止めた会話へ `claude --bg --resume <ID> "<文>"`（option なし） | 同じ会話 ID のまま起き、文が `origin.kind: human` の利用者の行として入り、モデルが答えた。出力は `note: woke session <頭8字> with its saved options (--name, --permission-mode, --model, …)`。モデル・権限の mode・名前は、立てた時の物のまま。0.6〜1.1 秒で返る |
| 同（option を付けて流す） | 止めた会話でも写しが立つ。出力は `the flags you passed started a copy as <頭8字>. Without flags, the same command continues <頭8字> itself.` |
| 動いている会話（手すき・作業中・端末で開いている・`claude -p --resume` が走っている）へ option なしで流す | 写しが立ち、写しが文に答えた。出力は `started a copy as <頭8字>`（`is already running in the background` か `is open in another Claude Code process`）。元の会話は変わらない |
| 止めた会話へ、起こす命令を同時に2つ流す | 2つとも「起こした」と返ったのに、利用者の行は1つだけ入った（もう1つは消えた）。fox では2つめが写しになった。1.5 秒後の3つめは写しになった |
| 起きた後継の最初の番 | 置き場で待っていた完了通知は、入力の hook の文脈として届いた。番の終わりに待つ hook が立った |
| 頭が `-` の文・改行・`"`・`%PATH%`・`$HOME`・`&`・`|`・`<>`・`^`・日本語を含む文を `--` の後に置いて流す | そのまま同じ文が届いた（Windows も） |
| 別のフォルダから流す | 同じ会話 ID のまま起きた |
| `claude rm` で消した会話へ、切り離す option を付けて流す | 同じ会話 ID で起きたが、名前は新しく付き直した |

## Decision

1. **起こすのは、人が旧い会話へ打った文の時だけ。** ADR 0063 で運ぶ入力のうち、種類が `prompt`（利用者の入力）の時だけ
   起こす。完了通知（`task-notification`）とほかの会話からの文（`peer`）では起こさない（今までどおり置き場で待つ）。
   slash command は今までどおり運ばない。
2. **起こすのは、止まっていると確かめられた時だけ。** 次を全部満たす時に限る。どれか1つでも確かめられなければ起こさず、
   0.16.32 の動き（置き場で待つ）にする。
   - 後継で待つ hook の process が生きていない（生きていれば、後継は動いている）。
   - 引き継ぎの記録が、後継を Claude Desktop へ移した印（`desktop.state: opened`）を持っていない。
   - 後継（今の続きの会話）に、Throughline の引き継ぎが進んでいない（予約・立ち上げ中・失敗の記録が無い）。
   - 後継の transcript が在る（無い会話 ID へ流すと、その ID で新しい会話が立つ）。最後に書かれてから 5 秒より経っている。
   - `claude agents --json --all` を読めて、後継の会話 ID の項目に、`pid` か `status` を持つ物が1つも無い。
     `kind: background` の項目があり、その `state` が `done` か `stopped`。
   - 文が 12,000 字以下で、NUL を含まない（Windows の命令行は全体で 32,767 字まで）。
3. **起こす命令。** `claude --bg --resume <後継の会話 ID> -- <文>` を、後継の project のフォルダで流す。option は付けない
   （裏の会話は立てた時の option を持っていて、option なしの時だけ同じ会話のまま起きる）。文は `--` の後に置く。
   旧い会話の会話ごとの環境変数（`CLAUDECODE`・`CLAUDE_CODE_ENTRYPOINT`・`CLAUDE_CODE_SESSION_ID`・`CLAUDE_PID`・
   `CLAUDE_EFFORT` など）は渡さない。旧い会話の `UserPromptSubmit` の hook の中で、その場で流す（一覧 10 秒・起こす命令
   15 秒で打ち切る。ふだんは合わせて 1〜2.5 秒）。結果が分かってから、打った人へ返す文を決める。
4. **起こす番は1つだけ。** 後継の置き場に印（`waking`）を排他で作れた hook だけが起こす。起こせた後も印は 60 秒残し、
   その間に届いた入力は起こさずに置き場へ置く（起きた後継の hook が、次の道具の前か番の終わりに受け取る）。
5. **渡す文を二重に届けない。** 起こす命令で渡す文は、置き場の受け取り済み（`claimed`）として書いてから命令を流す。
   起きた後継の入力の hook は、受け取り済みの文を文脈として渡さない。
   - 起きた（出力の ID が後継の頭8字）: 受け取り済みの文を消す。
   - 写しが立った（出力に `started a copy as`、または出力の ID が後継と違う）: 写しは渡した文で動き出すので、すぐ
     `claude stop`・`claude rm` で止めて一覧から消す（写しの transcript は消さない）。文は置き場へ戻す。後継は動いているので、
     後継の hook が受け取る。
   - 失敗した（命令が無い・立ち上がる前に失敗した・exit code が 0 でなく ID も無い）: 文を置き場へ戻す。
   - 分からない（時間切れ・exit code 0 で ID が読めない など）: 入れ直さない（ADR 0063 の 6 と同じ）。受け取り済みに残り、
     `auto-handoff status --host claude` の届いたか分からない数に出る。
6. **打った人へ返す文。**
   - 起きた: 「後継の会話が止まっていたので、Throughlineが起こして、この入力を後継の最初の入力として渡しました。後継は
     裏で作業を続けます」と、後継を開く命令。
   - 起こしている所だった: 「届いた入力は、後継の会話へ渡しました。後継は、先に届いた入力で起きている所です」と、従わない
     事がある旨と、後継を開く命令。
   - 動いていた（一覧で動いている・写しが立った・transcript が書かれたばかり）: 0.16.32 の「後継は動いています」の文。
   - 確かめられなかった・失敗した: 0.16.32 の「後継は今、入力を待ち受けていません」の文。
   - 分からない: 「起こそうとしましたが、起きて入力を受け取ったか確かめられませんでした。二重に届かないよう、この入力は
     入れ直していません。後継を開いて確かめてください」と、後継を開く命令。
7. **記録。** 運んだ記録（`forward.jsonl`）に `woken`・`wake-skipped`（理由）・`wake-copy`（写しの頭8字）・
   `wake-failed`・`wake-unknown` を足す。止めた記録（`redirects.jsonl`）と判定の記録に、起こした結果（`wake`）を足す。
   本文は書かない。
8. **止める上書き。** 環境変数 `THROUGHLINE_AUTO_HANDOFF_WAKE=off` の時は起こさない（0.16.32 の動き）。

## Consequences

- 後継が止まっている時も、旧い会話へ打った文は、打ち直さなくても後継へ届く。利用者の発言の形（`origin.kind: human` の
  利用者の行）で届くので、ADR 0063 の「後継のモデルが、運ばれた入力を利用者の依頼として扱わない」が起きない。
- 起きた後継は、立てた時のモデル・effort・権限の mode・名前（・リモートコントロール）で動く。Claude Code が片付けるまで
  （手すきで 61 分）裏で動き続け、利用枠を使う。片付けられた後で旧い会話へ文を打つたびに、もう一度起きる。
- 起きた後継の画面では、渡した文は利用者の発言として出る。旧い会話の画面には、止めた理由（「起こして渡しました」）と
  元の文が出る。
- 旧い会話へ打った文の hook が、後継が止まって見える時だけ、`claude agents`（と起こす命令）を流す分、1〜2.5 秒長くなる。
- 確かめた後から起こすまでの間に後継が動き出すと、写しが立つ。写しはすぐ止めて消すが、止めるまでの約 1 秒は写しが
  文で動く。
- `claude rm` で一覧から消した後継は、起こさない（立てた時の option の控えが消えていて、起こすと設定が変わる。端末で
  開いているかも確かめられない）。0.16.32 と同じに置き場で待つ。
- 12,000 字を超える文は起こさずに置き場で待つ。
- 起こす命令を同時に2つ流さないので、続けて打った2通めからは、起きた後継の hook の道（通知・文脈の形）で届く。
  その分は ADR 0063 と同じに、後継のモデルが従わない事がある。

## 確かめた事・確かめていない事

- 確かめた事は、Context の表と、この版の試験（CHANGELOG の 0.16.33）。
- 直した版を、本物の Claude Code 2.1.296 の裏の会話（Haiku）へ通した。Linux・macOS・Windows の3つ。利用者の設定の hook を
  外し、直した版を切り離した HOME で呼ぶ hook だけを付けた（直した版が流す `claude` は、HOME を本物へ戻す shim を通した）。
  結果は CHANGELOG と保守の記録に書く。
- 公開の後に、61 分で片付けられた裏の会話（3つの OS）へ option なしの起こす命令を流した。3つとも同じ会話・同じ名前のまま起き、
  文が利用者の行として入ってモデルが答え、置き場の完了通知が文脈として届き、番の終わりに待つ hook が立った（0.7〜1.3 秒）。
- 確かめていない:
  - Claude Desktop の画面とリモートコントロール（スマホ）で、起きた後継がどう見えるか。リモートコントロール付きで立てた
    後継が、起きた後もリモートコントロール付きか（立てた時の option の控えには入る）。
  - Windows で `claude` が単体の `claude.exe` の時の、文の渡り方（確かめた fox の `claude` は npm の shim で、Throughline は
    `claude.ps1` を PowerShell から呼ぶ。記号と改行を含む文は、この道でそのまま届いた）。
  - 本物の自動継続の後継での実地（入れた後の追跡で、`forward.jsonl` の `woken` を読む）。
