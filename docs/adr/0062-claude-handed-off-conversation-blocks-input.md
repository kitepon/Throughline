# ADR 0062: 引き継ぎ済みの Claude の会話へ届いた入力は、モデルを動かさずに止めて、後継の場所を返す

- Status: Accepted
- Date: 2026-10-14

## Context

Claude Code の自動継続（ADR 0033）は、文脈が一杯になった会話を止め、裏の新しい会話（後継）へ作業を引き継ぐ。
引き継いだ後も、旧い会話は消えない。旧い会話へは、入力が届き続ける。

- 旧い会話が裏で起こした作業（`run_in_background` の道具など）の完了通知。作業は旧い会話の process の下で動き続け、
  終わると旧い会話へ通知が届く。
- 人が旧い会話へ打った文。端末や一覧で旧い会話を開いたまま打つと、そこへ届く。
- ほかの会話から届いた文。

この製品が旧い会話でしていたのは、道具を断る事だけだった（`PreToolUse`。理由に後継の場所を書く）。入力が届くたびに、
文脈がほぼ一杯の旧い会話でモデルが1回動き、文だけで答える。届いた入力は後継へ渡らない。自動圧縮の合図も来続ける。

2026-10-13 の Windows の実機の1日で、引き継いだ後の旧い会話へ届いた入力は 191 行だった（完了通知 171、人の入力の形 19、
ほかの会話からの文 1。行の種類と時刻だけを読んだ。本文は読んでいない）。人の入力の形のうち 17 行は、引き継ぎの後の3時間に
1つの旧い会話へ届いていて、後継へは届いていない。別の旧い会話では、引き継ぎの後の 24 分に完了通知が 114 通届いていた。

Claude Code 2.1.296 で、次を実機で確かめた（Linux。後に macOS と Windows でも同じ）。

- 裏の作業の完了通知でも `UserPromptSubmit` が走る。`prompt` は `<task-notification>` で始まる。
- `UserPromptSubmit` が `{"decision":"block","reason":…}` を返すと、完了通知でも人の入力でも、user 行は書かれず、モデルは動かず、
  Stop も走らない。transcript には `system` の `informational` の行が1つ入る。人が打った時は、理由と元の文
  （`Original prompt: …`）が打った人へ返る。
- 裏で起こした道具は、結果の行に `toolUseResult.backgroundTaskId` を持ち、結果の文に出力の file の場所
  （`Output is being written to: …`）を持つ。完了通知は `<task-id>` と `<status>` を持つ。

届いた入力を後継へ自動で届ける形は、hook を1つ増やし、後継ごとに待つ process が要る。作り込む所が多い。利用者の決め
（2026-10-14）は「先に、旧い会話で止めて後継の場所を見せる形を入れ、続けて、後継へ届ける形を作る」。この ADR は先の分を決める。
届ける形は、別の ADR で決める。

## Decision

1. `UserPromptSubmit` の入口（`prompt-submit`）で、その会話に引き継ぎの記録があり、後継が残っている時、入力を止める
   （`redirectClaudeHandedOffPrompt`）。返すのは `{"decision":"block","reason":…}`。
   - 止めるのは、記録の状態が、後継が立った後（`launched`・`sent`・`unknown`）で、後継の transcript が在る時
     （`successorRemains`。期限の過ぎた記録を消さずに残す時の条件と同じ）。
   - 人の入力・完了通知・ほかの会話からの文を、同じに止める。
   - 理由の文は、道具を断る時の文と同じにする。引き継ぎ ID と、今の続きの会話を開く命令を書く。
2. 止めない物:
   - 引き継ぎの記録が無い会話（ほとんどの会話）。記録の file が無ければ、何も読み込まずに先へ進む。
   - 後継がまだ立っていない会話（予約・止めた直後・立ち上げ中・失敗）。その間の入力は、今までどおり。
   - 後継の transcript が無くなった会話。
   - 後継自身（記録が無い）。継続の指示と、後継の最初の入力は止まらない。
   - subagent の中の入力。
   - Aiterm が起こした席の会話（ADR 0057）。席は今は引き継がない。席を外す前の版が引き継いだ席が残っていても、呼び手は
     席の番の終わりを待っている。止めると番が始まらず、呼び手は答えを受け取れない。席は今までどおり、文で答える。
3. 理由の文に書く後継は、今の続きの会話にする。後継がさらに引き継がれていれば、その先を書く
   （`resolveClaudeAutoHandoffSuccessor`）。道具を断る時の文も同じに直す。
   - 書く命令は `claude attach <頭8字>` と、`claude --resume <会話 ID>`。`claude rm` で一覧から消した後継は、
     transcript が残っていて `claude attach` では開けない（`No job matching`）。`claude --resume` なら開ける。
4. 止めた回は、`~/.throughline/claude-auto-handoff/redirects.jsonl` に1行残す（時刻・旧い会話の ID・引き継ぎ ID・後継の頭8字・
   入力の種類 `prompt` か `task-notification`）。入力の本文は書かない。判定の記録（`inheritance-decision.log`）にも
   `prompt-redirect` を1行残す。こちらも本文は書かない。
5. 完了通知は旧い会話で止まり、後継へは届かない。代わりに、引き継ぐ時に、前の会話が裏で動かしていて、終わった通知がまだ
   来ていない作業の一覧を、後継の最初の指示（現在地）へ載せる（`readRunningBackgroundTasks`）。
   - 一覧は transcript から作る。裏で起こした道具の結果の行（`backgroundTaskId`）から、`<status>` を持つ完了通知
     （user 行か、ターンの途中に届いた `queued_command`）が届いた物を除く。途中の知らせ（`<status>` の無い通知）が来ただけの
     作業は、まだ動いている物として残す。
   - 載せるのは、道具の名前・対象（命令や説明の頭）・作業の ID・出力の file の場所。新しい順に 10 件まで。残りは件数だけ。
   - 後継には「終わった通知は、この会話へは届かない。結果が要る時は、出力の file を読んで確かめる」と書く。
6. 止める判定は、DB を開かない。記録の file だけを読む。

## Consequences

- 引き継ぎ済みの会話へ入力が届いても、モデルは動かない。文脈がほぼ一杯の会話で、通知のたびに1回動く事が無くなる。
- 旧い会話へ打った文は、理由と元の文が返る。利用者は、後継で打ち直す（届ける形が入るまで）。
- 完了通知は後継へ届かない（今までも届いていない）。後継は、引き継ぎの時に受け取った一覧と出力の file で確かめる。引き継ぎの
  後に旧い会話が新しく裏の作業を起こす事は無い（道具が断られる）。
- `claude -p --resume <旧い会話>` のように script から旧い会話へ入力を送った時も止まる。標準出力に理由と元の文が返り、
  終了 code は 0。
- 後継を `claude rm` で消しても、transcript が残る間、旧い会話は止まったままになる（道具も今までどおり断られる）。
  理由の文の `claude --resume <会話 ID>` で後継を開ける。後継の transcript まで消すと、旧い会話の入力は通る
  （道具は、記録が期限で消えるまで断られる。今までどおり）。
- `redirects.jsonl` は増える一方で、この版では古い行を消さない（1行 約 220 バイト。1日 200 行で約 44KB）。
- Codex・Grok・Cursor は変えない。Codex の旧タスクへ届く入力は、ADR 0039・0040 が別に扱っている。

## 確かめた事・確かめていない事

- 確かめた:
  - 単体試験（記録が無い・後継が立っていない・後継の transcript が無い時は止めない、人の入力と完了通知を止める、席の会話と
    subagent は止めない、後継の先を示す、止めた記録に本文を書かない、公開 CLI の `prompt-submit` の出力、裏の作業の一覧の作り方、
    後継の現在地の文）。
  - 本物の Claude Code 2.1.296 の裏の会話（Haiku）へ、直した版の `prompt-submit` を通した。Linux・macOS・Windows の3つ。
    利用者の設定の hook を外し（`--setting-sources project,local`）、直した版を切り離した HOME で呼ぶ hook だけを付けた。
    旧い会話の役が裏で `sleep 25` を起こし、番を終えた所で、後継の役の会話への引き継ぎの記録を切り離した置き場へ置いた。
    3つの OS とも同じ結果だった。

    | 見た事 | 結果 |
    |---|---|
    | 番を終えた旧い会話の、裏で動いている作業の一覧 | 1 件。出力の file の場所を読めて、その file が在る |
    | 裏の作業の完了通知 | 止まった。transcript に入ったのは `queue-operation` 2 行と `system` の `informational` 1 行。user 行も assistant 行も無い |
    | 人の入力（`claude -p --resume <旧い会話>`） | 止まった。理由と元の文が返り、終了 code 0 |
    | 後継を `claude rm` で消した後 | 後継の transcript は残る。`claude attach` は `No job matching` で終了 code 1。旧い会話への入力は止まる。`claude --resume <後継の会話 ID>` は通る |
    | 後継の transcript も消した後 | 旧い会話への入力は通り、モデルが答える |
    | 切り離した置き場の失敗の記録 | 無し |
    | 本物の置き場の判定の記録にある、試しの会話の ID | 0 |

  - 直した版の裏の作業の読み手を、本物の記録へ当てた（読むだけ。数だけ出す）。10/10 から動いた記録で、Linux 172 本のうち
    7 本に 8 件、macOS 73 本のうち 2 本に 2 件、Windows 109 本のうち 13 本に 25 件。どれも出力の file の場所を読めた
    （Windows は `PowerShell` の道具が 21 件、`Bash` が 4 件）。読み手が落ちた記録は無い。
- 確かめていない:
  - 端末の画面・Claude Desktop・リモートコントロール（スマホ）で、止めた時にどう見えるか。確かめたのは、裏の会話への
    完了通知と、`claude -p --resume` の入力。
  - ほかの会話から届いた文（`SendMessage`）を止めた時に、送り手へ何が返るか。
  - 本物の自動継続で、裏の作業を持つ会話が引き継がれた時の、後継の現在地の文。単体試験と、読み手の実機の確かめまで。
    入れた後の追跡で読む。
