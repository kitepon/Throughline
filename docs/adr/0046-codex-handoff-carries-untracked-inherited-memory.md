# ADR 0046: 前任をさかのぼれない記憶を受け取った Codex のタスクも引き継ぎ、受け取った記憶をそのまま後継へ渡す

日付: 2026-10-10

## Context

Codex Desktop の自動継続は、旧タスクが Throughline の記憶（`## Throughline: 自動継続文脈`・`Active Work Context`・
`New Codex Thread Handoff` で始まる developer の文）を受け取っていて、その前任が自動継続の記録に無い時、
`handoff_memory_lineage_untracked` で引き継ぎを止めていた。後継へ渡す記憶は、自動継続の記録をさかのぼって集める。
さかのぼれない前任の作業は集められないので、黙って落とさないための決まりだった。

2026-10-10、macOS の実機で、手動の引き継ぎ（`$throughline`。`New Codex Thread Handoff`）で 10/8 に始めたタスクが、
この理由で止まった。止めた順番が問題だった。

- 自動継続は、`PreCompact(auto)` の hook でターンを止めてから、worker が引き継げるかを調べる。断った時、止めたターンは戻らない。
- 途中で止めたタスクは、Codex が順番待ちを動かさない。ほかの道具が入れた返信も始まらない（ADR 0045 と同じ）。
- 次に人が入力しても、文脈は上限のままなので `PreCompact(auto)` でまた止まり、同じ理由で断る。受け取った記憶は消えないので、
  このタスクは何度入力しても引き継げない。

受け取った記憶の本文は、旧タスクの rollout の最初の developer の文に残っている（実機の例は 10,006 字）。
旧タスクのモデルが、それより前の作業について持っていた記憶は、この本文だけだった。

## Decision

1. 前任をさかのぼれない記憶を受け取ったタスクも、引き継ぐ。`handoff_memory_lineage_untracked` は出さない。
2. 受け取った記憶の本文（最初の1つ）を、引き継ぎの記録（`runtime_json.inheritedMemory`）へ残す。120,000 字を超える分は切り、
   元の字数と切った事を残す。
3. 後継へ渡す記憶に、「系列の最初のタスクが受け取っていた記憶（そのまま）」の節として載せる。L1・L2 より前に置く。
   元の `## Throughline: …` の見出しは「（元の見出し: …）」へ書き換え、後継の記憶の見出しを1つに保つ。
4. その後継がさらに引き継ぐ時も、系列をさかのぼって同じ本文を載せる。
5. 凍結した詳細の取得（`auto-handoff detail`）の対象には入れない。本文そのものを載せているので、取得する物が無い。
6. 自動継続の記録に前任があるタスクの扱い（記録をさかのぼって L1・L2 を集める）は変えない。

## Consequences

- 手動の引き継ぎで始めたタスク、ほかの端末や消えた記録から続いたタスクも、自動継続で引き継げる。
- 後継の記憶は、受け取った記憶の分だけ長くなる（上限 120,000 字）。引き継ぎを重ねても、同じ本文を1回載せるだけで増えない。
- 受け取った記憶より前の作業の L2・L3 は、後継から取得できない。旧タスクでも取得できなかったので、失う物は無い。
- 0.16.12 までで、この理由で止まっていたタスクは、次の入力か `auto-handoff resume --operation <ID>` で引き継がれる。
