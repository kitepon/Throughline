# ADR 0045: Codex の旧タスクの順番待ちに残った入力は、引き継ぎを断らずに後継へ運ぶ

日付: 2026-10-10

## Context

Codex Desktop の自動継続は、旧タスクの公式の順番待ち（`thread/queue/list`）に入力が残っていると、
`handoff_source_input_pending` で引き継ぎを止めていた。後継を作る前に、未処理の入力を取りこぼさないための決まりだった。

2026-10-09、Windows の実機で、この理由の失敗が2つのタスクに7回続いた。どちらのタスクも、そのまま使われなくなった。

- 1つ目のタスク: 13:17 と 14:43 に止まり、14:45 が最後の書き込み。
- 2つ目のタスク: 20:55 に止まり、21:06〜21:07 の4回の入力も全部止まった。21:08 が最後の書き込み。

原因は、止める順番と Codex の順番待ちの決まりの組み合わせにあった。

- 自動継続は、`PreCompact(auto)` の hook でターンを止めてから、worker が順番待ちを見る。
- Codex は、順番待ちの入力を「その入力でターンを始めた時」に消す（`codex-rs/ext/queue/src/service.rs` の
  `dispatch_if_idle`。`StartIfIdleSubmission::Started` の後に `delete_locked`）。順番待ちに残っている入力は、まだ送られていない。
- 途中で止めたタスク（`AgentStatus::Interrupted`）では、Codex は順番待ちを動かさない（同じ file の `wake_if_loaded` と
  `on_thread_idle`）。次に人が送ったターンが普通に終わるまで動かない。
- 旧タスクは文脈が上限に達しているので、次に人が送ったターンも `PreCompact(auto)` で止まる。順番待ちは空にならず、
  引き継ぎは同じ理由で止まり続ける。利用者には、何を打ってもタスクが止まるように見える。

順番待ちに入力が入るのは、ターンが動いている間に届いた物（利用者が続けて打った文、ほかの道具が
`thread/queue/add` で入れた通知や返信）。長いターンの間に1つ届くだけで、このタスクは引き継げなくなる。

Codex の app-server には、順番待ちを読む・入れる・消す口がある（`thread/queue/list`・`thread/queue/add`・
`thread/queue/delete`）。別の process からも使える。

## Decision

1. 旧タスクの順番待ちに入力が残っていても、引き継ぎを断らない。`handoff_source_input_pending` は出さない。
2. 後継が作業を続けたのを確かめた後（`continued` の直後）に、旧タスクの順番待ちの入力を、順番を保って後継の順番待ちへ運ぶ。
   後継へ `thread/queue/add`（`input` と `clientUserMessageId` はそのまま）で入れてから、旧タスクから `thread/queue/delete` で消す。
   後継の最初のターン（継続の指示）は始まっているので、運んだ入力はその後ろに並び、ターンが終わるたびに1つずつ始まる。
3. 二重に送らない。運ぶ入力の ID を、入れる前に引き継ぎの記録（`runtime_json.queueCarry.moving`）へ書き、入った後に
   `moved` へ移す。入れた結果が分からない入力（応答が切れた、途中で worker が終わった）は `unknown` へ入れ、入れ直さない。
   その入力は旧タスクの順番待ちに残る。Codex がはっきり断った入力も旧タスクに残す。
4. 運べなくても、引き継ぎの `state` は変えない。後継はもう作業を続けている。理由と数は worker のログに残す。
5. 後継がさらに引き継ぐ時も同じ。運んだ入力がまだ後継の順番待ちに残っていれば、次の後継へ運ぶ。
6. 途中で止まった引き継ぎ（`failed`・`unknown`）では、順番待ちを動かさない。やり直しで `continued` になった時に運ぶ。
7. 引き継ぎ済みの旧タスクへ後から届く入力の扱い（ADR 0039）は変えない。この ADR が扱うのは、引き継ぎの時点で残っていた入力だけ。

## Consequences

- 順番待ちに入力があるタスクも引き継げる。0.16.11 までで止まっていたタスクは、次の入力でやり直しが動き、引き継がれる
  （その時点で順番待ちに残っている入力は、全部後継へ運ばれる）。
- 運んだ入力は、後継の継続の指示のターンが終わった後に実行される。旧タスクで待っていた順番と同じ。
- ほかの道具が旧タスクの ID で持っている配送の記録は、後継の ID へは書き換わらない。入力そのものは後継で実行される。
- 入れた結果が分からない入力は、旧タスクの順番待ちに残る。旧タスクは引き継ぎ済みなので、その入力は実行されない。
  数は `auto-handoff status --operation <ID>` では出ないので、worker のログ（`queue carried`）で読む。
