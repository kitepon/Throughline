# ADR 0068: 起動結果を待ってから旧い会話を止める

- 日付: 2026-10-17
- 状態: 採用
- 関連: [ADR 0067](0067-claude-failed-handoff-releases-source.md)、[ADR 0014](0014-two-phase-handoff-ghost-baton.md)

## 問題

ADR 0067 は失敗後の再停止を廃止したが、最初の PreToolUse は worker の起動だけを
待って旧い応答を終了させていた。その後の起動失敗では、旧い応答は自動で続かない。
また、worker が途中の本文を先に DB へ確定すると、失敗後に元の作業が続いた時に
完了した本文を既存の部分捕捉として読み飛ばすおそれがある。

## 決定

1. PreToolUse は道具を実行する前の待ち時間を使い、同じ handoff の受領か失敗まで待つ。
   同時に来た道具も同じ記録を待ち、worker は一度だけ立てる。
2. 後継・受領が無い確定した失敗なら、最初の道具から continue:true を返す。
   元の応答を終了させず、そのまま作業を続ける。失敗記録と元の transcript は保持する。
3. 受領があれば旧い道具を deny / continue:false にする。結果不明も二重実行を防ぐため
   止める。210秒を過ぎても結果が無ければ unknown/handoff_source_wait_timeout とする。
4. 進行中のターンの DB 捕捉は worker の起動前には行わない。実際の後継の最初の
   UserPromptSubmit が handoff ID で前任を確定した時に、合流前に捕捉する。
   後継が生まれなかった失敗では、旧い会話の通常の Stop が完了した本文を保存する。
5. 自分の PreToolUse hook の timeout だけを15秒から240秒へ更新する。
   既存の hook 登録を移行し、他製品の hook と利用者の権限・モデルは変えない。

既存の記録形式と状態名は維持する。`stopped` は道具が実行されず保留されている段階を含み、
元の応答を終了させる出力は受領後だけ返す。

## 検証

- 最初の並列道具の間に worker が失敗すると、両方の道具を通す。worker は一度だけ。
- 起動IDだけでは旧い応答を終了させず、受領後に両方の道具を止める。
- 起動失敗では bodies が増えず、元の完了後は最終回答まで一組だけ回収できる。
- 後継の最初の入力では、合流前に L2 と L3 を捕捉し、従来の原文・道具入出力を引き継ぐ。
- 待機期限、既存の failed の継続、unknown の二重実行防止、hook の導入・移行を検査する。
